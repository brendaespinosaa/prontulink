# Requisitos do Sistema – ProntuLink

## 1. Requisitos funcionais

Os requisitos funcionais descrevem as operações que o protótipo deve oferecer.

- Permitir o cadastro de pacientes e o registro de informações pessoais.
- Permitir a edição e exclusão de cadastros.
- Disponibilizar pesquisa de pacientes por nome ou CPF.
- Permitir a criação e o preenchimento de fichas de anamnese odontológica.
- Organizar as perguntas da anamnese por etapas.
- Permitir o salvamento das informações preenchidas.
- Disponibilizar a consulta dos registros cadastrados.
- Permitir a exportação das fichas em PDF.
- Permitir a exportação e importação de backups em JSON.

## 2. Requisitos não funcionais

Os requisitos não funcionais estão relacionados à qualidade e às condições de utilização do sistema.

- Apresentar uma interface simples e intuitiva.
- Organizar as informações de forma clara e acessível.
- Facilitar a navegação entre as funcionalidades.
- Permitir a utilização em navegadores compatíveis.
- Adaptar a interface a diferentes tamanhos de tela.
- Considerar a privacidade e a proteção das informações clínicas.
- Utilizar exclusivamente dados fictícios durante as simulações e os testes.

## 3. Requisitos futuros

Algumas funcionalidades são importantes para uma futura evolução do projeto, mas ainda não estão implementadas no protótipo atual.

- Implementar autenticação de usuários.
- Criar diferentes níveis de acesso conforme o perfil profissional.
- Permitir o compartilhamento controlado de informações entre profissionais autorizados.
- Avaliar a integração com outros sistemas de saúde.
- Implementar mecanismos adicionais de segurança e proteção dos dados.

## 4. Observação

Os requisitos funcionais apresentados correspondem às funcionalidades disponíveis no protótipo desenvolvido. Os requisitos futuros representam possibilidades de evolução do sistema e não devem ser considerados funcionalidades já implementadas.

O protótipo possui finalidade acadêmica e demonstrativa, utilizando armazenamento local no navegador. Portanto, não deve ser utilizado para armazenar dados reais de pacientes ou substituir sistemas clínicos em produção.
